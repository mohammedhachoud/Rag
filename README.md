# RAG Retrieval Benchmark

A reproducible benchmark for comparing sparse and dense retrieval in a retrieval-augmented generation (RAG) workflow. The project extracts text from PDFs, creates token-aware corpora, indexes embeddings in Qdrant, evaluates BM25 and dense retrieval, analyzes failures, and can generate grounded answers with a local Ollama model.

## What is included

- PDF text extraction with page-level source metadata
- Token-aware 256- and 512-token chunks with a 32-token overlap
- BM25 sparse retrieval with `rank-bm25`
- Dense retrieval with `BAAI/bge-small-en-v1.5` and Qdrant
- A 100-query, manually reviewed evaluation set
- Precision@5, Recall@5, MRR, and latency measurements
- Per-query failure analysis exported as JSON and CSV
- A dense-retrieval RAG pipeline backed by Ollama

## Prerequisites

- Python 3.10 or newer
- Qdrant running at `http://localhost:6333` for dense retrieval
- Ollama running at `http://localhost:11434` for answer generation only
- An internet connection on the first run to download `BAAI/bge-small-en-v1.5`

The default generation model is `granite4.1:3b`; make sure it is available in Ollama before running the RAG pipeline.

## Setup

From the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Prepare the data

The repository already contains processed corpora and evaluation data. To rebuild them from source PDFs, run the following steps.

### 1. Extract PDF text

Place text-based PDFs in `data/raw/`, then run:

```powershell
python src/preprocessing/extract_text.py
```

The default output is `data/processed/documents.json`. Custom paths are supported:

```powershell
python src/preprocessing/extract_text.py --input path/to/pdfs --output path/to/documents.json
```

Scanned or image-only PDFs require OCR, which is not included.

### 2. Create token chunks

```powershell
python src/preprocessing/chunk_documents.py
```

This creates `data/processed/chunks_256.json` and `data/processed/chunks_512.json`. Chunking is configured in `src/preprocessing/chunk_documents.py`:

```python
MODEL_NAME = "BAAI/bge-small-en-v1.5"
CHUNK_SIZES = [256, 512]
CHUNK_OVERLAP = 32
```

### 3. Index dense embeddings

Start Qdrant, then run:

```powershell
python src/ingestion/ingest_embeddings.py
```

The script creates or updates these collections:

- `rag_dense_256`
- `rag_dense_512`

## Run retrieval examples

The example scripts use a built-in sample question and print the five highest-ranked chunks:

```powershell
python src/retrieval/bm25.py
python src/retrieval/dense.py
```

Dense retrieval requires the Qdrant collections created during ingestion.

## Run the benchmark

Validate the evaluation data first:

```powershell
python tools/validate_evaluation_dataset.py
```

Then compare BM25 and dense retrieval across both chunk sizes:

```powershell
python src/evaluation/benchmark.py
```

The benchmark reads `data/evaluation/synthetic_eval.json`, evaluates all four retrieval configurations at `top_k=5`, prints a summary, and writes `results/benchmark_results.json`.

Metrics reported for each system are:

- Precision@5
- Recall@5
- Mean reciprocal rank (MRR)
- Mean, p50, and p95 retrieval latency

For details about query construction and relevance judgments, see [`data/evaluation/README.md`](data/evaluation/README.md).

## Analyze retrieval failures

After running the benchmark:

```powershell
python src/evaluation/failure_analysis.py
```

This classifies misses, partial recall, distractors, chunk-size effects, lexical gaps, and possible semantic drift. It writes:

- `results/failure_analysis.json`
- `results/failure_analysis.csv`

## Ask a question with the RAG pipeline

With Qdrant and Ollama running:

```powershell
python -m src.rag.pipeline "What are the four AI RMF core functions?"
```

The pipeline retrieves five chunks from `rag_dense_512`, sends the top three chunks to Ollama, and prints a JSON response containing the answer, retrieved evidence, and generation timing statistics.

## Regenerate the evaluation set

`tools/generate_synthetic_queries.py` rebuilds the project-specific 100-query dataset from the current chunk files:

```powershell
python tools/generate_synthetic_queries.py
```

The generator currently writes `data/synthetic_queries.txt`. Review generated relevance labels before replacing the curated evaluation file.

## Configuration

Important defaults are defined directly in the source:

| Setting | Default | Location |
|---|---|---|
| Embedding model | `BAAI/bge-small-en-v1.5` | preprocessing, ingestion, and dense retrieval modules |
| Qdrant URL | `http://localhost:6333` | `src/retrieval/dense.py` |
| Dense collections | `rag_dense_256`, `rag_dense_512` | ingestion and dense retrieval modules |
| Benchmark `top_k` | `5` | `src/evaluation/benchmark.py` |
| Ollama host | `http://localhost:11434` | `src/generation/ollama_client.py` |
| Ollama model | `granite4.1:3b` | `src/generation/ollama_client.py` |

`OLLAMA_HOST` can be used to override the default Ollama endpoint.

## Notes

- Run commands from the repository root so local `src` imports resolve correctly.
- Ingestion is idempotent for stable chunk IDs: existing Qdrant collections are reused and points are upserted.
- BM25 runs locally from the JSON chunk files; it does not require Qdrant.
- Dense retrieval and the benchmark require Qdrant to be available.
- Answer generation is local and requires Ollama; retrieval evaluation does not.
